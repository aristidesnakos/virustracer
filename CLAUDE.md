## Commands

```bash
npm run dev       # start dev server (localhost:3000)
npm run build     # production build
npm run lint      # ESLint
npm test          # unit tests (Vitest, jsdom; tests/**/*.test.{ts,tsx})
npm run test:e2e  # Playwright e2e (uses the running dev server on PLAYWRIGHT_PORT, default 3000)
node scripts/update-toll.mjs   # manually refresh every automated outbreak's toll.json (keyless); --outbreak=<slug> for one, --adapter=wikipedia|eody-report|cdc-measles|cdc-nndss for one kind
node scripts/update-toll.mjs --outbreak=west-nile-greece-2026 --report=<pdf-url> [--report=...]   # read specific EODY reports (backfill/repair; needs pdftotext)
node scripts/fetch-feeds.mjs   # manually run feed updater (OPENROUTER_API_KEY optional)
node scripts/diagnose-model.mjs [--mode=verify|matrix]   # probe the feed model (needs the key: run it via the "Diagnose feed model" workflow, workflow_dispatch only)
node scripts/probe-feeds.mjs [--only=<text>]   # keyless check of candidate news sources (status, article text, keyword matches); the sandbox cannot reach them, so run the "Probe feed sources" workflow
node scripts/backfill-toll.mjs [--dry-run]   # one-off: import daily toll history from the Wikipedia article's revisions; supersedes stored snapshots the history contradicts
node scripts/toll-history.mjs --outbreak=<slug> --from=YYYY-MM-DD [--to=...]   # list a tracked article's revisions with editor, summary and parsed figures (traces a rejected decrease)
node scripts/backfill-raw.mjs [--dry-run]    # one-off: archive the raw infobox of older snapshots; --outbreak=<slug> for one
node scripts/archive-sources.mjs [--dry-run] # manually run the Internet Archive link archiver
node scripts/update-nursing-homes.mjs [--dataset=respiratory|infection-control] [--force]   # nursing-home layer (NHSN + CMS F880), keyless
```

## Architecture

Single-page outbreak dashboard (Next.js 16 App Router, React 19, Tailwind v4, TypeScript). Tracks the 2026 Bundibugyo Ebola outbreak (DRC + Uganda), the 2026 Bangladesh measles outbreak, the 2026 measles outbreaks in the United States, Candida auris in the United States in 2026 and the 2026 West Nile virus season in Greece with automatically tracked tolls, plus the archived 2026 MV Hondius hantavirus record.

**Data flow — three layers:**

0. **Outbreak registry** — `src/data/outbreaks/index.ts` lists every outbreak (`listOutbreaks`, `getOutbreak(slug)`, `getDefaultOutbreak`, `DEFAULT_OUTBREAK_SLUG`); Pages live at `/outbreaks/[slug]` and the API at `/api/v1/outbreaks/[slug]/*` (paths built by `src/lib/outbreak-paths.ts`); `/` is the snapshot home (status groups and ranked cards, see below), and the un-prefixed `/api/v1/{toll,metrics,signals}` are permanent aliases for the default outbreak (callers rely on them: never remove). Each outbreak is one `OutbreakDefinition` (`src/data/outbreaks/types.ts`): `slug`, `disease`, `status` (`active|waning|over|watch`), `source` (`wikipedia-infobox|official-report|manual`), SEO text, and the curated data below. Components and `src/lib/*` take the outbreak's data as props or a `slug`; nothing imports a specific outbreak except the registry. `SITE_NAME` = "Outbreak Files" and `SITE_TAGLINE` (`src/lib/site.ts`) are the site brand (og:site_name, title template, WebSite/Organization JSON-LD, masthead kicker, share card, API attribution); an outbreak's `title` names the event, e.g. "Ebola Outbreak 2026", never the site. The `.mjs` scripts cannot import TypeScript, so they keep a matching entry in `scripts/lib/outbreak-registry.mjs`; `tests/outbreak-registry.test.ts` fails if slug, status, disease or Wikipedia page drift apart. The script registry lists every outbreak; only entries with `toll`/`feed` are fetched (`selectOutbreaksWith`), and one named with `--outbreak` that has neither is skipped with a log line. Fetched data lives in `data/outbreaks/<slug>/{toll,live,candidates,signals}.json` (`src/lib/outbreak-data.ts` builds the paths and rejects non-slug input). Metric assumptions are per outbreak: `OutbreakDefinition.metrics` (`PathogenAssumptions` in `metrics.ts`: `serialInterval` mean/SD/source and `caseToDeathDays`) is required, and `computeMetrics(points, outbreak.metrics)` has no default, so a disease cannot inherit another's values. A value without a verified source is `null` and the indicator is left out (measles: no Rt, no delay-adjusted fatality); `/data` lists every outbreak's assumptions. `metrics.reportingCadence: "weekly"` (an official weekly report) lowers `minReadingsInTwoWeeks` to `WEEKLY_MIN_READINGS_IN_TWO_WEEKS` (2); `rtShortNote` words the Rt tile's "Not shown" reason. The API keeps its flat `assumptions` field names. The Wikipedia adapter (`toll.page`) works for any article with an `{{Infobox outbreak}}`; `toll.ignoreFields: ["recovered"]` in the script registry blanks a field a source uses differently, and the deaths field may hold several figures (`parseDeaths`: the confirmed-case one, never an "all cases" total). An outbreak whose Deaths figure is narrower than all deaths sets `summary.deathsQualifier` (e.g. "among confirmed cases"), which the stat strip, home card, descriptions and share card print after "Deaths".

1. **Curated data** — each outbreak file under `src/data/outbreaks/` (`ebola-bundibugyo-2026.ts`, `measles-bangladesh-2026.ts` and the hand-curated `hantavirus-mv-hondius-2026.ts`) is the hand-verified source of truth. It holds `casesTimeline` (milestones; `confirmed`/`suspected`/`deaths`/`recovered` are all optional), `monitoringData` (country table; DRC provinces are sub-rows via `parentIso` and excluded from the total), `spreadStops`, `caseLocations` (map bubbles), `summary` and the identity fields. Every entry needs a `source`.

2. **Auto-tracked toll snapshots** — `data/outbreaks/<slug>/toll.json` (`{ lastChecked, snapshots[] }`) is written by `scripts/update-toll.mjs`, which loops over the automated outbreaks in `scripts/lib/outbreak-registry.mjs` (one failing logs an annotation and the rest continue), reads each one's Wikipedia infobox (Ebola: "2026 Ebola epidemic") via the MediaWiki API, parses confirmed/suspected/deaths/recovered from the `{{Infobox outbreak}}` in the lead section (`toll.page` in the registry; parsing and the sanity checks live in the pure helpers in `scripts/lib/toll.mjs`), sanity-checks against the previous snapshot (confirmed/deaths/recovered never decrease, no >25% jump in confirmed/deaths unless the last snapshot is >7 days old, deaths <= confirmed), and writes one snapshot per UTC day with an `?oldid=` permalink to the exact revision. On failure it logs a GitHub Actions warning/error annotation and exits 0. **Withdrawn figures:** a rejected reading refreshes `lastChecked` and records `rejected: {since, reason}` in toll.json (an `::error::` once it is older than `REJECTION_ALERT_HOURS`, 48). If it contradicts only the latest one or two snapshots and passes every check against the snapshot before them, `planCorrection` records `pendingCorrection`; once that persists `SUPERSEDE_PERSIST_HOURS` (24) over `SUPERSEDE_MIN_RUNS` (2) runs, `supersedeSnapshots` moves those snapshots to `superseded` (with `supersededAt`/`supersededReason`; never deleted, raw files kept) and the reading is stored. This ended the Ebola freeze of 2026-11-02 to 11-09: DRC's INSP published 5,376 deaths and withdrew it within hours, our run had stored the revision carrying it, and every later reading was rejected as a decrease; the snapshot sits under `superseded` with the edit history as `supersededEvidence`. `scripts/backfill-toll.mjs` does the same for history (`mergeBackfill`: a stored snapshot the daily revisions contradict is superseded and that day's reading offered instead; stored snapshots win ties), and `node scripts/toll-history.mjs --outbreak=<slug> --from=<date>` lists every revision with editor, summary and figures (run it from a runner or locally; the sandbox cannot reach Wikipedia). The site and API read only `snapshots`/`lastChecked`. `src/lib/toll.ts` (`getTollData(slug)`) reads the file at request time and `src/lib/timeline.ts` (`mergeTimeline`, `latestDate`) merges the snapshots with the curated `casesTimeline`; curated wins on the same date. `page.tsx` passes the merged `timeline` to `StatStrip` and `CasesChart`.

2b. **Official weekly report (West Nile virus, Greece)** — no Wikipedia infobox exists, so `west-nile-greece-2026` has `toll.adapter: "eody-report"` in the script registry (`tollAdapter(o)`; default `"wikipedia"`) and `source.kind: "official-report"` on the site. `update-toll.mjs` reads EODY's announcements RSS (`toll.feedUrl`, items whose title has `toll.titleIncludes`), downloads every report in the feed not yet stored (by URL or by report date), oldest first, runs `pdftotext -layout` (poppler-utils; locally from Homebrew), and parses it with `scripts/lib/eody.mjs` (`parseReportText`: Greek or English; the "up to DD/MM/YYYY" date, the case total and deaths from the sentence, cross-checked against Table 1, which must add up; any mismatch is an `::error::` and nothing is stored). The snapshot is dated by the report's "up to" date, not the fetch date; `sourceUrl` is the PDF and `sourceSha256` its hash. Validation uses `WEEKLY_STALE_PREV_DAYS` (3) so a week of real early-season growth passes the jump check, and `applySnapshot(..., { appendUnchanged: true })` keeps a quiet week. It runs in its own workflow (see Workflow), not in `update-data.yml`. The region table and map markers in `west-nile-greece-2026.ts` are hand-copied from the report's Table 3 (deaths are national only, so one table row). The 12 Aug 2026 report was never found; the chart interpolates the gap.

2c. **Official weekly page (US measles, CDC)** — no Wikipedia article has an outbreak infobox for the national picture (checked 2026-11-02; the Pennsylvania and "Measles resurgence" articles have none), so `measles-us-2026` has `toll.adapter: "cdc-measles"` and `source.kind: "official-report"`. `update-toll.mjs` (`updateFromCdcMeasles`) reads three documents on `www.cdc.gov` (`isCdcUrl`: https and that host only, redirects off it refused, 3 MB cap): the national page (`toll.pageUrl`), `measles_hosp.json` (`toll.hospUrl`, the summary table's data) and `MeaslesCasesMap.json` (`toll.mapUrl`, cases per jurisdiction). `scripts/lib/cdc.mjs` (`extractPageExcerpt`, `buildReading`, `parseCdcReading`) accepts a reading only if they agree: the headline sentence's total equals the data file's and the jurisdictions plus international visitors, the map sums to the sentence's jurisdiction figure and count, and all three carry the same as-of date; any mismatch is an `::error::` and nothing is stored. The CDC counts by rash-onset year and publishes weekly (cases reported as of noon Thursday, page updated the next day); the snapshot is dated by that Thursday, `toll.year` (2026) must match the year in the sentence, and a page that has moved to another year logs a `::notice::` and stores nothing (set the status by hand). The page has no archive of past weeks, so history starts at the first run and grows one reading a week; each run reads only the current page. `suspected`/`recovered` are null (the CDC counts confirmed cases only). Deaths: **the headline is the figure the page displays** (a hand-typed cell, "3*", footnoted "subject to change"). `measles_hosp.json` carries a `total_deaths` the page does not show (5 on 2026-10-29), and Pennsylvania's health department reports at least five of its own; every run logs a `::warning::` while the page and its data file differ, and the stat strip, card and descriptions say "Deaths in the CDC's count" (`summary.deathsQualifier`). Validation uses `WEEKLY_STALE_PREV_DAYS` and `applySnapshot(..., { appendUnchanged: true })`; a *decrease* (the CDC revises deaths down) is rejected for manual review, like every reader. The region table (11 states with 100+ cases as sub-rows of one national row; the CDC publishes no deaths by state) and map markers in `measles-us-2026.ts` are hand-copied from `MeaslesCasesMap.json` and dated; they go stale between hand updates, which is why each row shows its `asOf`. It runs in `update-data.yml` (step "Update CDC measles figures", twice a day, most runs only refresh `lastChecked`); the CDC may refuse GitHub's runners as EODY does, in which case the step logs a warning and exits 0 and the maintainer runs `node scripts/update-toll.mjs --outbreak=measles-us-2026` locally.

2d. **Official weekly table (Candida auris, US, CDC NNDSS)** — `candida-auris-us-2026` has `toll.adapter: "cdc-nndss"` and `source.kind: "official-report"`. `update-toll.mjs` (`updateFromCdcNndss`) makes one Socrata query to the dataset "NNDSS Weekly Data" (`x9gk-5huc` on `data.cdc.gov`; `isNndssUrl`: https and that host only, redirects not followed, 12 MB cap, an answer that hits the 50,000-row limit is refused) for the labels `"Candida auris, clinical"` and `"Candida auris, screening"` (`toll.labels`) from `toll.year` on. `scripts/lib/nndss.mjs` (`groupWeeks`, `buildNndssReading`, `parseNndssReading`): m1 current week, m2 previous-52-week max, m3 cumulative YTD, m4 previous year's YTD (the dataset's column descriptions and CDC's NNDSS Reader's Guide); a measure is a number or a flag (`-` no reported cases, `U`, `N`, `NN`, `NP`, `NC`), never both, and flags count as 0. A week is accepted only if all 70 reporting areas appear once per label, every row is that year and week, and for m1/m3/m4 the states add up to each census region, the territories to "U.S. Territories", the nine regions to "U.S. Residents" (50 states, DC and NYC, no territories) and U.S. Residents + territories + non-U.S. residents to "Total" (all of these held for every 2026 week on 2026-11-06; m2 is a maximum and the weekly m1 values do not add up to m3, so neither is checked); any mismatch is an `::error::`, nothing from that week or later is stored and it is retried next run. Snapshot: dated by the Saturday ending the MMWR week (`mmwrWeekEnding`: week 1 ends on the first Saturday on or after 4 January; checked against CDC's weekly COVID death dataset, where 2026 week 1 ran 4–10 Jan and 2025 had 53 weeks), `confirmed` = U.S. Residents cumulative clinical cases, `screening` = cumulative screening cases (colonisation: never in `suspected`, never added to clinical), `mmwrYear`/`mmwrWeek`, `deaths`/`suspected`/`recovered` null (NNDSS collects no deaths; `validateSnapshot(..., { allowNullDeaths: true })`), `sourceUrl` = a query for that week's rows. The table keeps every week as published (CDC: "presented as published each week"), so an empty store is backfilled from week 1 and later runs read only weeks after the newest stored one; a stored week whose figures differ in the table logs a `::warning::` and is left alone. Counts are provisional and can fall: 2026 weeks 17 (1,816) and 18 (1,881) were below week 16 (2,022), so they were rejected for manual review and are not in `toll.json` (the chart interpolates). Raw: each week's rows (`serializeNndssReading`, one row per line) at `data/raw/report/cdc-nndss-auris-<date>-<sha12>.txt`, re-verified by `verifyNndssRaw` in `tests/raw.test.ts`. Year rollover: rows for a later year log a `::notice::` (status and `toll.year` set by hand). Site: no deaths anywhere: `summary.deathsNotReported` (stat strip shows a "Not reported" tile and no fatality, home card and share card drop the deaths figure), `summary.casesLabel` "Clinical cases" and `summary.screeningLabel` (stat tile, chart series, CSV column) relabel the counts; `computeMetrics` returns `deathsReported: false` and nulls every death figure; the home ranking counts it as zero new deaths. The region table (15 states with 100+ clinical cases) and map markers (the table's own `geocode` points) in `candida-auris-us-2026.ts` are hand-copied from the week 43 table and dated. It runs in `update-data.yml` (step "Update CDC NNDSS figures").

3. **Live feed data** — `live.json`, `candidates.json` and `signals.json` (per outbreak folder) are written by `scripts/fetch-feeds.mjs`, a thin wiring of the real HTTP, OpenRouter client and files around `runOutbreakFeeds` in `scripts/lib/feed-run.mjs` (every side effect injected, so `tests/feed-run.test.ts` runs it on fake RSS and a fake model; helpers in `feed-items.mjs`, `feed-model.mjs`, `pool.mjs` (`mapPool`, `retry`), `atomic.mjs`, each with its own test). For each automated outbreak it fetches the feeds listed in the registry concurrently (Ebola: WHO news RSS, the WHO Disease Outbreak News API, CIDRAP and two ECDC feeds, plus three Google News queries), keyword-filters them (`feed.strongKeywords`, `feed.contextualKeywords`; a source's own `match` list replaces them for that source, e.g. a Dhaka paper's health section), and (if `OPENROUTER_API_KEY` is set) asks DeepSeek via OpenRouter for a summary and a country candidate per item, 4 items at a time with the two calls of an item in parallel; 429/5xx/network errors are retried with backoff (the SDK's own retries are off). **Model settings:** both calls send `reasoning: {enabled: false}` and `max_tokens: 1000` (`SUMMARY_PARAMS`/`CANDIDATE_PARAMS` in `feed-model.mjs`). Root cause of the ~23% empty answers (diagnosed 2026-11-08, `scripts/diagnose-model.mjs`, run 42482944426): OpenRouter routes the model to providers that reason by default (Baidu, Parasail, SiliconFlow, GMICloud, Venice) and others that do not (Wafer, DeepInfra); reasoning tokens count against `max_tokens`, so the old 150/250-token budgets ran out before any answer (`finish_reason: "length"`, content null). An unusable answer (empty, cut off, not JSON) is retried once and then thrown as `ModelResponseError`, whose message names `finish_reason`, provider and reasoning tokens; `failureCause()` gives a code (`length_reasoning`, `length`, `empty`, `invalid_json`, `http_<status>`, `timeout`, `network`) and each outbreak's summary line counts failures by cause, lists failed feeds with their HTTP status and counts headline-only inputs (Google News RSS descriptions are only "headline publisher", `isHeadlineOnly`). **Article-text sources:** Google News RSS gives only "headline publisher" and its links cannot be followed to the article, so every outbreak also reads sources that carry text (chosen with `scripts/probe-feeds.mjs`, listed with results in `docs/public-data-sources.md` "News feeds"); they come before the Google News queries in each `sources` list because duplicate headlines are dropped in feed order and the text copy must win (`tests/outbreak-registry.test.ts` enforces it). `parseSourceItems` reads RSS or Atom (`parseFeedItems`: the longer of description and `content:encoded`/Atom content, plain text, capped at `MAX_ITEM_TEXT` 1500) or, for `format: "who-don-api"`, WHO's JSON (`whoDonItems`: Summary + Overview + Epidemiology, link to the public DON page). Dedupe (`titleKeys`) strips " - Publisher" only from Google News headlines, so WHO's "Ebola disease - Uganda" and "Ebola disease - DRC" stay distinct. WHO reuses one title for every update of a running outbreak, so `WHO_DON` sets `titlesRepeat` and its items are deduped by title and date (`classifyFeedItems` `datedTitles`); before that only 2 of 15 Ebola DONs survived. New items are still displayed newest-first, so older text items (a DON from October) are checked for candidates but may not reach the 20 displayed. **Summary prompts (version `SUMMARY_VERSION` 2, 2026-11-09):** an item whose only text is its headline (`isHeadlineOnly`: every Google News item) gets `headlinePrompt` (restate the headline as one sentence, add no figures, dates or context, end with "<publisher> reported."); an item with real text gets `summaryPrompt` (lead with a stated toll, a date only if the text gives one, never describe the text or what it lacks). Every answer is tidied (`cleanSummary` drops a dateless "As of the article's reporting," lead-in) and checked (`summaryProblem`: "meta" for filler such as "the article does not provide a death toll" or "the provided text", "too_short" for a stub); a bad answer is retried once and then fails with that cause. Version 1 asked for "the as-of date" on bare headlines, so it invented dates ("As of March 2026" on a November headline) and wrote filler in 32 of 100 displayed summaries. Items record `summaryVersion`; **Summary repair:** an item stored with the raw description because its summary call failed carries `summaryFallback: true` (a model summary has `false`); items stored before the flag are detected once by the rule in `needsSummaryRepair` (the summary starts with the headline minus " - Publisher", as a Google News description does). Each run re-requests summaries for displayed items that need it (`MAX_SUMMARY_REPAIRS_PER_RUN` 20, `MAX_SUMMARY_REPAIR_ATTEMPTS` 3 per item): fallbacks, filler or stubs (`summaryProblem`), and Google News items summarised before `SUMMARY_VERSION` (once); a sound summary from the current version is never re-requested. A repair gives the model the original text when it has it, else the headline alone (`repairInput`), never the bad summary. Rules: (a) a **summary** (display only) is requested only for new items that will be among the newest 20 after merging (`pickSummaryIds`); every new item still gets a **candidate extraction**, because candidates feed the ledger; items beyond `MAX_NEW_PER_FEED` (15 per feed) are only marked processed, as before. (b) `candidates.json` carries `checkedIds` (capped at 1000): ids the model has already read, including those that named no country, so nothing is asked twice; the backfill covers stored `recentItems` not in `checkedIds` or `candidates`. A call that failed is never recorded as checked (a dropped item whose candidate call failed also stays unprocessed, so the next run retries it). (c) State is persisted after every finished item, atomically (temp file `.<name>.<pid>.tmp` then rename; `data/**/*.tmp` is git-ignored and stale temps are removed at start), in plan order, sorted by date then id, so a killed run keeps its work and reruns write the same bytes; `candidates.json` and `signals.json` are not rewritten when nothing changed. (d) Failures: a feed that fails is a warning; all feeds of an outbreak failing, or one kind of model call failing every time (3+ calls), throws for that outbreak after saving; the script exits 1 if any outbreak failed (`::error::` annotation each), and the workflow turns that into a red run without skipping the commit (see Workflow). The server reads the files at request time via `src/lib/live-data.ts` (`getLiveData(slug)`) and `src/lib/candidates-data.ts` (`checkedIds` is optional and never shown or served). Country candidates extracted from news are shown as Unverified.

**Nursing-home data layer (not outbreaks):** recurring measurements by state and by facility, kept apart from the outbreak registry: never registered as an `OutbreakDefinition`, never fed to `computeMetrics`, and the outbreak API is untouched. `scripts/update-nursing-homes.mjs` (step "Update nursing-home data" in `update-data.yml`; `--dataset=respiratory|infection-control`, `--force` re-reads unchanged sources) writes `data/nursing-homes/`; pure helpers in `scripts/lib/nhsn.mjs` and `scripts/lib/cms-f880.mjs` (tests `tests/nhsn.test.ts`, `tests/cms-f880.test.ts`). Hosts: `data.cdc.gov`, `www.cdc.gov`, `data.cms.gov` only (https, redirects off host refused, size caps). A fetch failure is a `::warning::`, a failed check an `::error::`, and either leaves that source's files untouched; exit 0. Every accepted extract's canonical CSV is archived gzip-compressed, write-once, as `data/raw/nursing-homes/<prefix>-<date>-<sha12>.csv.gz` (`archiveGzipText`/`readGzipText` in `scripts/lib/raw.mjs`; the SHA-256 is of the uncompressed CSV); `tests/nursing-homes-raw.test.ts` re-derives every stored file from its archive. App side: `src/lib/nursing-homes.ts` (client-safe types, paths, calculations), `src/lib/nursing-homes-data.ts` (fs readers), `src/lib/nursing-homes-api.ts` (handlers), `src/components/NursingHomesDocs.tsx` (the sections on `/data#nursing-homes`, `/methodology#nursing-homes` and the home page, so those shared pages carry one import each), `src/lib/nursing-homes-sitemap.ts`. Pages: `/nursing-homes` (hub), `/nursing-homes/respiratory`, `/nursing-homes/infection-control`, `/nursing-homes/infection-control/[state]` (static, one per state file). API: `/api/v1/nursing-homes`, `/api/v1/nursing-homes/respiratory` (`series=counts|rates`, `state`, `from`, `to`, `format`), `/api/v1/nursing-homes/infection-control-citations` (`state` or `ccn`, `from`, `to`, `min_severity`, `format`; neither `state` nor `ccn` returns the per-state summary, since the full list is ~24k rows).

- **A. NHSN respiratory (residents, by jurisdiction only; CDC shows facility rows only to the facility).** Two CDC sources, because the open dataset lags: (1) Socrata `tscn-ryh9` on data.cdc.gov, COUNTS (`numres` residents present at least one day of the week, `faccount` homes with complete data, positives and hospitalisations per pathogen, vaccination); on 2026-11-06 its newest week was 2026-03-29 and its rows were last updated 2026-08-24, with no fresher data.cdc.gov dataset. Fetched only when the metadata's `rowsUpdatedAt` changes. Checks (all held for 78 weeks): weeks are Sundays; states/territories sum exactly to `USA` for every count column, and so do the 10 HHS regions; parts never exceed wholes; `pct_*` = numerator/`numres`; flu/RSV present nationally from 2025-01-12. Stored in `respiratory/counts.json` (columnar, regions dropped, null = missing, never zero). (2) The data file behind CDC's Nursing Home Data Dashboard, `https://www.cdc.gov/nhsn/modules/case-rates-covid-flu-rsv.json` (10 MB, gzip on the wire; the hospitalisation chart's file held identical data), RATES per 100,000 residents only, newest week 2026-11-01, updated Thursdays. Its rows are a cross product (each case rate repeated per hospitalisation virus); all copies must agree, every week needs a `USA` row, and the chart must still say "per 100,000 residents". Stored in `respiratory/rates.json`; `marked` is CDC's unexplained "Trigger: Dotted" flag (weeks Oct-Dec 2025). The dashboard's rates are close to but NOT equal to rates computed from the dataset's counts (different extract), so the two are never cross-checked and each is labelled with its source. Rates per 100k from counts use `numres` (the dataset's own denominator). Influenza/RSV are absent until the week ending 2025-01-05 (`ALL_PATHOGENS_FROM` = 2025-01-12): the chart starts there, earlier weeks stay in the API. The dataset's last weeks hold a fraction of the homes (6,743 vs ~12,600 on 2026-03-29): `thinlyReportedWeeks` (< 90% of the median of the 8 prior weeks) flags them, and the counts table shows the newest full week. A stored week missing from a new extract is an `::error::`.
- **B. CMS F880 infection-control citations (named facilities).** Provider Data Catalog "Health Deficiencies" `r5ix-sfxw`, filtered to `deficiency_tag_number=0880` through the query API (1,500 rows per page, sorted by `record_number`; 24,413 rows at 12,011 homes in release 2026-10-01, published 2026-10-28). About the last three inspection cycles per home, not a full history. Fetched only when the metastore's `modified`/`released` change; the metastore is re-read after paging and a change mid-read aborts. Checks: rows received = the API's count; tag 0880, prefix F, category "Infection Control Deficiencies", survey type Health; `processing_date` = `modified`; valid CCN, state, dates, A-L severity, cycle, Y/N flags and a known correction-status wording (`STATUS_CODES`); no duplicate rows. Stored: `infection-control/index.json` (every release ever fetched, with its raw path and checksum, so history builds up) and compact per-state files `infection-control/states/<ST>.json` for the LATEST release only (about 3 MB in all; older releases live in their ~700 KB raw archives, which keep every field). "Last 12 months" = surveys within the year ending on the release's processing date; "G or above" = G-L. Care Compare link: `https://www.medicare.gov/care-compare/details/nursing-home/<CCN>?state=<ST>` (medicare.gov is not reachable from the build sandbox; the form follows CMS's documented URLs). A 403 from data.cms.gov reported for a Python client with a custom user agent could not be reproduced on 2026-11-06 (urllib with its default and with the project user agent, and Node fetch, all got 200); the reader sends the project's `USER_AGENT`. **Wording rule:** inspection data, not outbreak data: "cited for an infection-control deficiency on <date>", never "outbreak" or "infected"; every row shows its survey date and CMS release, and the pages say a citation may have been corrected and can be disputed (IDR/IIDR). Corrections go to `CORRECTIONS_URL`.

**Derived metrics and public API:**

- `src/lib/metrics.ts` (`computeMetrics`) turns the daily `toll.snapshots` into weekly incidence, a growth rate with a Poisson 95% range, doubling/halving time, Rt (gamma serial interval, constants in `ASSUMPTIONS`) and three fatality ratios. It fills gaps by interpolation, never lets a cumulative count fall, and ends the 7-day windows on the latest day the total moved (at most `maxReportingLagDays` before the last reading) because the Wikipedia source is updated in batches; measuring to a stale flat day shows a false collapse. It returns `status: "insufficient_data"` rather than guessing when history is thin. Metrics use `toll.snapshots` only, not the merged timeline, to avoid cross-source jumps from curated rows. `src/lib/trend-summary.ts` writes the plain-language verdict; `TrendPanel.tsx` renders it (Fig. 3).
- Public, keyless, CORS-open JSON/CSV: `/api/v1/outbreaks` (list) and `/api/v1/outbreaks/[slug]/{toll,metrics,signals}` (404 JSON for an unknown slug), plus the un-prefixed aliases for the default outbreak. One implementation in `src/lib/api-handlers.ts` (`tollResponse`, `metricsResponse`, `signalsResponse`, `outbreaksListResponse`, `forOutbreak`) serves both; `tests/api-handlers.test.ts` checks alias and per-outbreak responses are identical apart from `meta.slug`. Pure helpers (query parsing, CSV, headers, `attributionFor(outbreak)`) in `src/lib/api.ts`. `/data` documents endpoints and the method; its assumptions are read from `ASSUMPTIONS` so docs cannot drift. Keep `/data` and `src/lib/metrics.ts` in sync.
- API call log: `src/proxy.ts` (matcher `/api/v1/:path*`) writes one `[api-call]` line per request with method, path, the accepted query params only, referrer host, country (`x-vercel-ip-country`) and user agent, never the IP (`apiCallLogLine` in `src/lib/api-call-log.ts`). Proxy runs before the CDN cache, so cached calls are logged too. Vercel request logs carry no caller identity of their own and are kept about 24 hours, so read them (`npx --yes vercel@latest logs --environment production --since 24h --json --query "/api/v1"`) within a day.
- `scripts/backfill-toll.mjs` takes the last Wikipedia revision of each UTC day, parses the infobox with the same parser as the daily updater, drops readings with deaths > confirmed (early revisions counted suspected deaths) and keeps the longest never-decreasing chain (`scripts/lib/backfill.mjs`) so vandalism/typos cannot poison the series. The article title, snapshot source label and user agent live in `scripts/lib/outbreak-registry.mjs`, shared with `update-toll.mjs`; it takes `--outbreak=<slug>` or runs every automated outbreak. Snapshots may carry `revisionTimestamp`.
- Early-signal ledger: `scripts/fetch-feeds.mjs` folds extracted candidates into `signals.json` (one row per country, first-seen date, never pruned; `scripts/lib/signals.mjs`). `src/lib/signals.ts` joins it to `monitoringData` at read time: a signal is confirmed once the table lists the country with cases, and `leadDays` needs the optional curated `firstConfirmed` date on that `MonitoringEntry`.
- `AlertsInterestWidget.tsx` (bottom-right pill, mounted once in `src/app/layout.tsx` so it shows on every page) is a demand test, not an alert system: one email field, posted with the page path to `/api/alert-interest` (`src/lib/alert-interest.ts` holds validation). Delivery needs `INTEREST_WEBHOOK_URL` and/or `RESEND_API_KEY` + `ALERT_INTEREST_EMAIL_TO` + `ALERT_INTEREST_EMAIL_FROM`; with none set, production returns 503 on purpose so sign-ups are not silently lost. Opens and sign-up summaries (never emails) are logged as `[alert-interest] ...`.

**SEO:** `src/lib/site.ts` holds `SITE_URL` (env `NEXT_PUBLIC_SITE_URL`, else the permanent domain `PRODUCTION_SITE_URL` = https://outbreakfiles.com in production builds, else localhost; the same constant lives in `scripts/lib/site.mjs` and `tests/seo.test.ts` checks they match); canonical, Open Graph, JSON-LD, sitemap and robots all read it. `layout.tsx` has site-level metadata only (title template, robots, generic keywords, OG/Twitter; no canonical, so every page sets its own and repeats `siteName`/`type` in `openGraph`); `outbreaks/[slug]/page.tsx` `generateMetadata` uses the outbreak's `seoTitle` (`title.absolute`), keywords and canonical, puts the latest toll in the description (`src/lib/seo.ts`) and renders WebPage/Dataset JSON-LD with per-outbreak `@id`s (the home page declares WebSite/Organization). `app/robots.ts`, `app/sitemap.ts` (one entry per registered outbreak; `lastmod` = date that outbreak's data last moved, never build time; priority by status via `SITEMAP_PRIORITY`), `app/opengraph-image.tsx` (site card) and `app/outbreaks/[slug]/opengraph-image.tsx` (per-outbreak card with the current toll) are generated. `/api/*` is `X-Robots-Tag: noindex` (next.config.ts). The `<title>`/keywords live in `outbreak.seoTitle`/`outbreak.keywords`.

**Brand mark:** `brand/mark.svg` (a file folder with a large red dot and two smaller ones spreading from it) is the one hand-edited source, and its `<style>` block holds the palette. `node scripts/build-brand.mjs` (needs `rsvg-convert` and `magick`; outputs are committed, CI never runs it) derives `src/app/icon.svg`, `favicon.ico` and `apple-icon.png`, which Next.js links by file name. `src/components/BrandMark.tsx` draws the same shapes inline (home masthead, outbreak kicker, both share cards); `tests/brand.test.ts` fails if the component or `icon.svg` drift from the source. Judge any change at 16px.

**Archival layer (long-term record):**

- Raw CDC reading: a `cdc-measles` snapshot's `rawPath` is `data/raw/report/<rawPrefix>-<date>-<sha12>.txt` too, but holds JSON, not `pdftotext` output: the page excerpt (headline paragraph, "Updated on" line, Total Deaths row), the year's `measles_hosp.json` data and the year's cases per jurisdiction (`serializeReading`). `verifyCdcRaw` re-runs the same cross-checks on it; `tests/raw.test.ts` does so for every archived file.
- Raw report text: an `eody-report` snapshot's `rawPath` is `data/raw/report/<rawPrefix>-<date>-<sha12>.txt`, the full `pdftotext` output it was parsed from (`archiveReportText`/`verifyReportRaw` in `scripts/lib/raw.mjs`, same write-once rule); `tests/raw.test.ts` re-parses every archived file.
- Raw infobox: every snapshot in `data/outbreaks/<slug>/toll.json` may carry `rawPath` (`data/raw/infobox/<revid>.txt`, one directory shared by every outbreak since revids are unique across Wikipedia; append-only, written with `wx`, never rewritten) and `rawSha256`. The file is the exact `{{Infobox outbreak}}` block the numbers were parsed from, so readings can be re-verified if the parser or Wikipedia's format changes (`extractInfobox` in `scripts/lib/toll.mjs`, `verifyRaw`/`archiveInfobox` in `scripts/lib/raw.mjs`). `update-toll.mjs` and `backfill-toll.mjs` write it; `node scripts/backfill-raw.mjs [--dry-run] [--outbreak=<slug>]` fills in older snapshots for each automated outbreak (one failing does not stop the rest), storing a revision only if its re-parsed numbers match. The API exposes `rawSha256` but not `rawPath`.
- Link archive: `scripts/archive-sources.mjs` (`scripts/lib/archive.mjs`) records Internet Archive captures in `data/archive.json`, one ledger for the whole site (one entry per URL, never pruned, keeps title/date/source and the `outbreak` slug that first cited it, so the record survives link rot and `live.json` rotation). For every registered outbreak, past records included (or `--outbreak=<slug>`), it covers `live.json` news items, `toll.json` Wikipedia `?oldid=` permalinks and literal URLs in `src/data/outbreaks/<slug>.ts` (the `links` hrefs), plus our own pages (`SITE_PAGES` in `scripts/lib/site.mjs`, kind `site`: re-captured weekly, always freshly saved, never marked failed, skipped on localhost). Capped per run, rate-limited, exits 0 on any error. Data API queries (`isApiQueryUrl`: Socrata `/resource/` and `/api/` URLs on `data.cdc.gov`, i.e. the C. auris weekly NNDSS `sourceUrl`s) are not collected: the Internet Archive mostly times out on them, one attempt can take a minute, and the committed raw copy in `data/raw/report/` is their durable record; their older ledger entries stay (the ledger is never pruned) but are never attempted again. The ledger is rewritten atomically after every URL (`onProgress`; stale temp files are removed at start), so a killed step loses at most the URL in flight. The run stops itself after `maxSlowFailures` (3) timeouts or network errors in a row (an HTTP error such as EODY's 520 answers quickly and does not count) and after `ARCHIVE_BUDGET_MS` (180000 in the workflow). Budget plus one worst-case link (about 90 s: 10 s Google News resolve, 15 s lookup, 60 s save, 5 s pacing) must stay under the step's 5-minute cap, or the runner kills the step and the run shows a red timeout. `src/lib/archive.ts` reads the ledger; the UI does not show archive links yet.

**Automation rule:** automation (GitHub Actions) never edits `src/data/outbreaks/*.ts`. Only the headline totals and chart are auto-updated; the province/country table, map bubbles, and `summary` are updated by hand.

**Workflow:** `.github/workflows/update-data.yml` runs at 08:00 and 20:00 UTC (and via `workflow_dispatch`, e.g. `gh workflow run update-data.yml`) in a concurrency group. Steps: `node scripts/update-toll.mjs --adapter=wikipedia`, then `node scripts/update-toll.mjs --adapter=cdc-measles` (US measles, see 2c), then `node scripts/update-toll.mjs --adapter=cdc-nndss` (Candida auris, see 2d), then `node scripts/update-nursing-homes.mjs` (nursing-home layer), then `node scripts/fetch-feeds.mjs`, then the data commit, then `node scripts/archive-sources.mjs` (capped at 5 minutes with `continue-on-error`, so a slow Internet Archive cannot skip the ledger commit, and run after the data commit, so it can never delay the data reaching the site), then a second commit of `data/archive.json` alone (the job limit is 22 minutes, raised from 10 on 2026-11-06 after 12 of 14 runs were cancelled before committing). `npm ci --omit=dev` installs only runtime dependencies: every script in this workflow imports node built-ins and `openai` only (re-check this when a script gains an import). The feed step (`id: feeds`) has its own `timeout-minutes: 12` and `continue-on-error: true`, so a hung or failed feed step never skips archive/commit, and the final step "Fail the run if feeds failed" (`if: always()` and the step's outcome is `failure` or `cancelled`) ends the run red so GitHub's failure email fires. The data commit (`data/outbreaks data/nursing-homes data/raw`; pull --rebase, push) comes right after the feed step and the ledger commit after the archive step, then a final `always()` step writes each outbreak's latest toll to the Actions step summary. Vercel redeploys on the commit. `OPENROUTER_API_KEY` is the only secret and is optional. West Nile Greece is fetched from the maintainer's Mac, because EODY answers GitHub runners with HTTP 403 (found 2026-10-07; never work around it with a spoofed User-Agent or a proxy): `scripts/mac/west-nile-updater.sh`, installed by `scripts/mac/install-west-nile-updater.sh` (`--uninstall` removes it) as the launchd job `local.outbreakfiles-west-nile` (09:30 and 21:30 local, log `~/Library/Logs/outbreakfiles-west-nile.log`), runs `update-toll.mjs` in a throwaway sparse clone in a temp folder (never in the working checkout), pushes when a report was stored or once a day for `lastChecked`, and on `season_over=true` opens the issue, notifies and unloads itself; `--dry-run` pushes nothing. `.github/workflows/update-west-nile.yml` is kept for `workflow_dispatch` only (to test whether EODY still blocks GitHub; restore its cron if a run reads the feed). Same concurrency group, `permissions: {}` at the top, three jobs: `update` (`contents: read`, checkout without persisted credentials, since the PDF is untrusted) installs poppler-utils, runs `update-toll.mjs --outbreak=west-nile-greece-2026` and uploads `data/outbreaks/west-nile-greece-2026` and `data/raw/report` as an artifact; `commit` (`contents: write`, fresh checkout) downloads it, checks toll.json's shape, EODY-only `sourceUrl`s and raw file names, refuses if anything else changed, then commits; `close-season` (below). The reader only fetches https URLs on `eody.gov.gr`/`www.eody.gov.gr` (`isEodyUrl`, redirects off EODY refused), caps a PDF at 20 MB while streaming, rejects future-dated reports and prints feed text on one line. The West Nile news feed and link archiving stay in `update-data.yml`. Season end: when no report in the feed is new, every matching item in it was readable, and the newest stored report is more than `SEASON_OVER_AFTER_DAYS` (21) days old, the script writes `season_over=true` to `$GITHUB_OUTPUT` (never on a fetch failure or an empty feed); the `close-season` job (`actions: write`, `issues: write`, nothing else) then opens one issue asking for the outbreak's `status` to be set by hand in both registries, and runs `gh workflow disable update-west-nile.yml` (re-enable with `gh workflow enable`).

**Component breakdown:**

- `src/app/outbreaks/[slug]/page.tsx` — Server Component; composes one outbreak's dashboard (stat strip, map, chart, table, feed); `notFound()` and `dynamicParams = false` for unknown slugs. Builds the merged `timeline` and passes it as a prop to `StatStrip` and `CasesChart`. An archived record (`isArchivedRecord`: status `over` or source `manual`) shows "Archived record · last verified <date>" and any `corrections`, and nothing live: no pulsing dot or fetch times, an "About this record" panel instead of an empty trend panel (the trend panel shows only with real toll snapshots), news as coverage at the time, no toll API in its Dataset JSON-LD. Optional definition fields drive the rest: `chartReference` (Ebola's PHEIC line), `tableSources`, `map` (`route` draws the dashed voyage line), `credit` (share-card footer, `shareCardFooter` in `src/lib/seo.ts`).
- `src/app/page.tsx` — snapshot home. `src/lib/home-snapshot.ts` (`buildSnapshot`, `compareSnapshots`, `groupByStatus`, `describeHome`) builds one `OutbreakSnapshot` per outbreak from `computeMetrics(toll.snapshots)` (never the merged timeline) and applies the published ranking rule: `STATUS_ORDER` (active, watch, waning, over), then 7-day new deaths, then 7-day new cases, then title; outbreaks with too little history sort last in their group. `OutbreakCard` shows places and the two dates (as of / checked, or "last verified" for curated outbreaks) on top, the newest figures beside a fluid `WeeklySparkline` (server SVG of weekly new cases) captioned by the plain-language trend result (`trendStatement`/`TREND_STATEMENT` in `trend-summary.ts`, also listed on `/methodology`) and the 7-day counts, and a footer with the source revision link, Dashboard and Data & API; the right-hand panel follows `trendPanelState` (readings exist: bars and result; no readings and the outbreak is over: a centred "Outbreak over"; no readings otherwise: "not enough data yet"). `TrendBadge` is now only used by `TrendPanel` (dashboard). Home JSON-LD adds CollectionPage/ItemList; the description names the top outbreaks with numbers.
- `src/app/methodology/page.tsx` and `src/app/about/page.tsx` — trust pages in the `StaticPage` shell with `SiteFooter`. `/methodology#ranking` publishes the ranking rule (keep it in sync with `compareSnapshots`; it reads `STATUS_ORDER` and `ASSUMPTIONS`); sanity-check numbers live in `src/lib/methodology.ts` and `tests/site-pages.test.tsx` fails if they drift from `scripts/lib/toll.mjs`. `/about` names Ari Nakos and sends corrections to GitHub issues (`CORRECTIONS_URL`).

On the home page it sits in the "Declared over" group. Hand-curated from WHO DONs, ECDC, RIVM, UKHSA and the Wikipedia case table (each row names its sources); last verified 2026-10-03.
