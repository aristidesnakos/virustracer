## Commands

```bash
npm run dev       # start dev server (localhost:3000)
npm run build     # production build
npm run lint      # ESLint
npm test          # unit tests (Vitest, jsdom; tests/**/*.test.{ts,tsx})
npm run test:e2e  # Playwright e2e (uses the running dev server on PLAYWRIGHT_PORT, default 3000)
node scripts/update-toll.mjs   # manually refresh every automated outbreak's toll.json (keyless); --outbreak=<slug> for one
node scripts/fetch-feeds.mjs   # manually run feed updater (OPENROUTER_API_KEY optional)
node scripts/backfill-toll.mjs [--dry-run]   # one-off: import daily toll history from the Wikipedia article's revisions
node scripts/backfill-raw.mjs [--dry-run]    # one-off: archive the raw infobox of older snapshots; --outbreak=<slug> for one
node scripts/archive-sources.mjs [--dry-run] # manually run the Internet Archive link archiver
```

## Architecture

Single-page outbreak dashboard (Next.js 16 App Router, React 19, Tailwind v4, TypeScript). Currently configured for the 2026 Bundibugyo Ebola outbreak (DRC + Uganda) with an automatically tracked death toll.

**Data flow — three layers:**

0. **Outbreak registry** — `src/data/outbreaks/index.ts` lists every outbreak (`listOutbreaks`, `getOutbreak(slug)`, `getDefaultOutbreak`, `DEFAULT_OUTBREAK_SLUG`); Pages live at `/outbreaks/[slug]` and the API at `/api/v1/outbreaks/[slug]/*` (paths built by `src/lib/outbreak-paths.ts`); `/` is the snapshot home (status groups and ranked cards, see below), and the un-prefixed `/api/v1/{toll,metrics,signals}` are permanent aliases for the default outbreak (callers rely on them: never remove). Each outbreak is one `OutbreakDefinition` (`src/data/outbreaks/types.ts`): `slug`, `disease`, `status` (`active|waning|over|watch`), `source` (`wikipedia-infobox|manual`), SEO text, and the curated data below. Components and `src/lib/*` take the outbreak's data as props or a `slug`; nothing imports a specific outbreak except the registry. `SITE_NAME` = "Outbreak Files" and `SITE_TAGLINE` (`src/lib/site.ts`) are the site brand (og:site_name, title template, WebSite/Organization JSON-LD, masthead kicker, share card, API attribution); an outbreak's `title` names the event, e.g. "Ebola Outbreak 2026", never the site. The `.mjs` scripts cannot import TypeScript, so they keep a matching entry in `scripts/lib/outbreak-registry.mjs`; `tests/outbreak-registry.test.ts` fails if slug, status, disease or Wikipedia page drift apart. Fetched data lives in `data/outbreaks/<slug>/{toll,live,candidates,signals}.json` (`src/lib/outbreak-data.ts` builds the paths and rejects non-slug input). Per-pathogen metric assumptions are not injected yet: `ASSUMPTIONS` in `metrics.ts` is global and Ebola-specific, so do that before adding a second pathogen.

1. **Curated data** — each outbreak file under `src/data/outbreaks/` (today `ebola-bundibugyo-2026.ts`) is the hand-verified source of truth. It holds `casesTimeline` (milestones; `confirmed`/`suspected`/`deaths`/`recovered` are all optional), `monitoringData` (country table; DRC provinces are sub-rows via `parentIso` and excluded from the total), `spreadStops`, `caseLocations` (map bubbles), `summary` and the identity fields. Every entry needs a `source`.

2. **Auto-tracked toll snapshots** — `data/outbreaks/<slug>/toll.json` (`{ lastChecked, snapshots[] }`) is written by `scripts/update-toll.mjs`, which loops over the automated outbreaks in `scripts/lib/outbreak-registry.mjs` (one failing logs an annotation and the rest continue), reads each one's Wikipedia infobox (Ebola: "2026 Ebola epidemic") via the MediaWiki API, parses confirmed/suspected/deaths/recovered from the `{{Infobox outbreak}}` in the lead section (`toll.page` in the registry; parsing and the sanity checks live in the pure helpers in `scripts/lib/toll.mjs`), sanity-checks against the previous snapshot (confirmed/deaths/recovered never decrease, no >25% jump in confirmed/deaths unless the last snapshot is >7 days old, deaths <= confirmed), and writes one snapshot per UTC day with an `?oldid=` permalink to the exact revision. On failure it logs a GitHub Actions warning/error annotation and exits 0. `src/lib/toll.ts` (`getTollData(slug)`) reads the file at request time and `src/lib/timeline.ts` (`mergeTimeline`, `latestDate`) merges the snapshots with the curated `casesTimeline`; curated wins on the same date. `page.tsx` passes the merged `timeline` to `StatStrip` and `CasesChart`.

3. **Live feed data** — `live.json` and `candidates.json` (per outbreak folder) are written by `scripts/fetch-feeds.mjs`. For each automated outbreak it fetches the feeds listed in the registry (Ebola: WHO news RSS plus three Google News queries), keyword-filters them (`feed.strongKeywords`, `feed.contextualKeywords`), and (if `OPENROUTER_API_KEY` is set) summarizes via OpenRouter DeepSeek and extracts country candidates. The server reads them at request time via `src/lib/live-data.ts` (`getLiveData(slug)`) and `src/lib/candidates-data.ts`, called in the Server Component `page.tsx`. Country candidates extracted from news are shown as Unverified.

**Derived metrics and public API:**

- `src/lib/metrics.ts` (`computeMetrics`) turns the daily `toll.snapshots` into weekly incidence, a growth rate with a Poisson 95% range, doubling/halving time, Rt (gamma serial interval, constants in `ASSUMPTIONS`) and three fatality ratios. It fills gaps by interpolation, never lets a cumulative count fall, and ends the 7-day windows on the latest day the total moved (at most `maxReportingLagDays` before the last reading) because the Wikipedia source is updated in batches; measuring to a stale flat day shows a false collapse. It returns `status: "insufficient_data"` rather than guessing when history is thin. Metrics use `toll.snapshots` only, not the merged timeline, to avoid cross-source jumps from curated rows. `src/lib/trend-summary.ts` writes the plain-language verdict; `TrendPanel.tsx` renders it (Fig. 3).
- Public, keyless, CORS-open JSON/CSV: `/api/v1/outbreaks` (list) and `/api/v1/outbreaks/[slug]/{toll,metrics,signals}` (404 JSON for an unknown slug), plus the un-prefixed aliases for the default outbreak. One implementation in `src/lib/api-handlers.ts` (`tollResponse`, `metricsResponse`, `signalsResponse`, `outbreaksListResponse`, `forOutbreak`) serves both; `tests/api-handlers.test.ts` checks alias and per-outbreak responses are identical apart from `meta.slug`. Pure helpers (query parsing, CSV, headers, `attributionFor(outbreak)`) in `src/lib/api.ts`. `/data` documents endpoints and the method; its assumptions are read from `ASSUMPTIONS` so docs cannot drift. Keep `/data` and `src/lib/metrics.ts` in sync.
- `scripts/backfill-toll.mjs` takes the last Wikipedia revision of each UTC day, parses the infobox with the same parser as the daily updater, drops readings with deaths > confirmed (early revisions counted suspected deaths) and keeps the longest never-decreasing chain (`scripts/lib/backfill.mjs`) so vandalism/typos cannot poison the series. The article title, snapshot source label and user agent live in `scripts/lib/outbreak-registry.mjs`, shared with `update-toll.mjs`; it takes `--outbreak=<slug>` or runs every automated outbreak. Snapshots may carry `revisionTimestamp`.
- Early-signal ledger: `scripts/fetch-feeds.mjs` folds extracted candidates into `signals.json` (one row per country, first-seen date, never pruned; `scripts/lib/signals.mjs`). `src/lib/signals.ts` joins it to `monitoringData` at read time: a signal is confirmed once the table lists the country with cases, and `leadDays` needs the optional curated `firstConfirmed` date on that `MonitoringEntry`.

**SEO:** `src/lib/site.ts` holds `SITE_URL` (env `NEXT_PUBLIC_SITE_URL`, else the permanent domain `PRODUCTION_SITE_URL` = https://outbreakfiles.com in production builds, else localhost; the same constant lives in `scripts/lib/site.mjs` and `tests/seo.test.ts` checks they match); canonical, Open Graph, JSON-LD, sitemap and robots all read it. `layout.tsx` has site-level metadata only (title template, robots, generic keywords, OG/Twitter; no canonical, so every page sets its own and repeats `siteName`/`type` in `openGraph`); `outbreaks/[slug]/page.tsx` `generateMetadata` uses the outbreak's `seoTitle` (`title.absolute`), keywords and canonical, puts the latest toll in the description (`src/lib/seo.ts`) and renders WebPage/Dataset JSON-LD with per-outbreak `@id`s (the home page declares WebSite/Organization). `app/robots.ts`, `app/sitemap.ts` (one entry per registered outbreak; `lastmod` = date that outbreak's data last moved, never build time; priority by status via `SITEMAP_PRIORITY`), `app/opengraph-image.tsx` (site card) and `app/outbreaks/[slug]/opengraph-image.tsx` (per-outbreak card with the current toll) are generated. `/api/*` is `X-Robots-Tag: noindex` (next.config.ts). The `<title>`/keywords live in `outbreak.seoTitle`/`outbreak.keywords`.

**Archival layer (long-term record):**

- Raw infobox: every snapshot in `data/outbreaks/<slug>/toll.json` may carry `rawPath` (`data/raw/infobox/<revid>.txt`, one directory shared by every outbreak since revids are unique across Wikipedia; append-only, written with `wx`, never rewritten) and `rawSha256`. The file is the exact `{{Infobox outbreak}}` block the numbers were parsed from, so readings can be re-verified if the parser or Wikipedia's format changes (`extractInfobox` in `scripts/lib/toll.mjs`, `verifyRaw`/`archiveInfobox` in `scripts/lib/raw.mjs`). `update-toll.mjs` and `backfill-toll.mjs` write it; `node scripts/backfill-raw.mjs [--dry-run] [--outbreak=<slug>]` fills in older snapshots for each automated outbreak (one failing does not stop the rest), storing a revision only if its re-parsed numbers match. The API exposes `rawSha256` but not `rawPath`.
- Link archive: `scripts/archive-sources.mjs` (`scripts/lib/archive.mjs`) records Internet Archive captures in `data/archive.json`, one ledger for the whole site (one entry per URL, never pruned, keeps title/date/source and the `outbreak` slug that first cited it, so the record survives link rot and `live.json` rotation). For every automated outbreak (or `--outbreak=<slug>`) it covers `live.json` news items, `toll.json` Wikipedia `?oldid=` permalinks and literal URLs in `src/data/outbreaks/<slug>.ts` (the `links` hrefs), plus our own pages (`SITE_PAGES` in `scripts/lib/site.mjs`, kind `site`: re-captured weekly, always freshly saved, never marked failed, skipped on localhost). Capped per run, rate-limited, exits 0 on any error. `src/lib/archive.ts` reads the ledger; the UI does not show archive links yet.

**Automation rule:** automation (GitHub Actions) never edits `src/data/outbreaks/*.ts`. Only the headline totals and chart are auto-updated; the province/country table, map bubbles, and `summary` are updated by hand.

**Workflow:** `.github/workflows/update-data.yml` runs at 08:00 and 20:00 UTC (and via `workflow_dispatch`, e.g. `gh workflow run update-data.yml`) in a concurrency group. Steps: `node scripts/update-toll.mjs`, then `node scripts/fetch-feeds.mjs`, then `node scripts/archive-sources.mjs`, then commits `data/outbreaks data/archive.json data/raw` (pull --rebase, push), then a final `always()` step writes each outbreak's latest toll to the Actions step summary. Vercel redeploys on the commit. `OPENROUTER_API_KEY` is the only secret and is optional.

**Component breakdown:**

- `src/app/outbreaks/[slug]/page.tsx` — Server Component; composes one outbreak's dashboard (stat strip, map, chart, table, feed); `notFound()` and `dynamicParams = false` for unknown slugs. Builds the merged `timeline` and passes it as a prop to `StatStrip` and `CasesChart`.
- `src/app/page.tsx` — snapshot home. `src/lib/home-snapshot.ts` (`buildSnapshot`, `compareSnapshots`, `groupByStatus`, `describeHome`) builds one `OutbreakSnapshot` per outbreak from `computeMetrics(toll.snapshots)` (never the merged timeline) and applies the published ranking rule: `STATUS_ORDER` (active, watch, waning, over), then 7-day new deaths, then 7-day new cases, then title; outbreaks with too little history sort last in their group. `OutbreakCard` shows figures, `TrendBadge` (shared with `TrendPanel`), `WeeklySparkline` (server SVG of weekly new cases), as-of date and source revision link (curated outbreaks show "last verified"). Home JSON-LD adds CollectionPage/ItemList; the description names the top outbreaks with numbers.
- `src/app/methodology/page.tsx` and `src/app/about/page.tsx` — trust pages in the `StaticPage` shell with `SiteFooter`. `/methodology#ranking` publishes the ranking rule (keep it in sync with `compareSnapshots`; it reads `STATUS_ORDER` and `ASSUMPTIONS`); sanity-check numbers live in `src/lib/methodology.ts` and `tests/site-pages.test.tsx` fails if they drift from `scripts/lib/toll.mjs`. `/about` names Ari Nakos and sends corrections to GitHub issues (`CORRECTIONS_URL`).
- `src/components/StatStrip.tsx` — headline stats; takes the `timeline` and `summary` props (latest merged point for cases/deaths, trends, case fatality, plus the summary figures).
- `src/components/MapLoader.tsx` — thin `"use client"` wrapper that uses `next/dynamic` with `ssr: false` to avoid SSR for MapLibre GL.
- `src/components/OutbreakMap.tsx` — Client Component; MapLibre GL map with CARTO dark-matter tiles. Takes `spreadStops` (first-detection sites) and `caseLocations` props (via `MapLoader`) and renders bubbles labelled with confirmed cases and deaths, with hover popups.
- `src/components/CasesChart.tsx` — Recharts "Cumulative deaths & cases" chart; takes the merged `timeline` prop.
- `src/components/MonitoringTable.tsx` — region table from the `monitoringData` prop; province rows (`parentIso`) render as sub-rows under their country.
- `src/components/FeedUpdates.tsx` — renders `recentItems` from the outbreak's `live.json`.
- `src/lib/outbreak-trend.ts` (trend deltas), `src/lib/timeline.ts` (curated + snapshot merge), `src/lib/toll.ts` (reads the outbreak's `toll.json`), `src/lib/live-data.ts`, `src/lib/candidates-data.ts`.

**Map:** MapLibre GL JS with CARTO dark-matter tiles (free, no API key). `OutbreakMap` must be loaded client-side only — always go through `MapLoader`.

**Tests:** unit tests live in `tests/` (Vitest + Testing Library, `tests/setup.ts`; includes `toll.test.ts` for the scraper helpers and `timeline.test.ts` for the merge); e2e specs in `e2e/` (Playwright, run against the dev server).

**Env vars:**
- `OPENROUTER_API_KEY` — optional; used only by `scripts/fetch-feeds.mjs` (summaries + country extraction). The app and `scripts/update-toll.mjs` run without it.
